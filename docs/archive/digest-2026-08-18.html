VMware vCenter flaws move from disclosed to actively exploited, as AI keeps accelerating both sides of the threat landscape

↪ Follow-up to the vCenter thread opened Aug 9 (patch released, no known exploitation) and to the AI-adversary-tooling thread tracked since Aug 5.

Attackers are now actively exploiting the critical, unauthenticated vCenter Server vulnerabilities (CVE-2026-59309/59310) that Broadcom patched July 29, using them to gain persistent remote access on unpatched systems. Separately, Microsoft's August Patch Tuesday fixed 421 CVEs including one exploited zero-day, and Google/CrowdStrike report North Korea's Kimsuky group is now running AI on its own infrastructure to build malware and phishing content, while Lazarus Group used a Windows zero-day to backdoor defense and aerospace firms in France, Germany, Brazil and India.

What’s new The vCenter flaws' jump from 'patched, no known exploitation' (Aug 9) to confirmed in-the-wild exploitation is the most actionable new development; the Kimsuky/Lazarus detail adds concrete state-actor cases behind the AI-enabled-attack trend this digest has tracked since Aug 5.
How outlets frame it Security-trade coverage (Hacker News, SecurityWeek) treats this as a patch-urgency story; Google/CrowdStrike's framing emphasizes AI as now accelerating both vulnerability discovery and offensive tooling simultaneously, a broader strategic point beyond any single CVE.
Context

vCenter Server is VMware's central management console for virtualized data centers — compromising it can hand an attacker control over every virtual machine an organization runs, which is why unauthenticated, unpatched vCenter flaws are rated among the most severe enterprise risks.

⚑ Any organization running on-prem vCenter that hasn't yet applied the July 29 VMSA-2026-0006 patch should treat this as urgent — exploitation is now confirmed, not theoretical.
